# Что такое балансировка в Kubernetes?

**Балансировка нагрузки (load balancing)** — это распределение входящих запросов между несколькими подами (репликами) одного сервиса, чтобы:

- не перегружать один под,
- обеспечить отказоустойчивость (если один под умер — запросы идут на другие),
- ускорить обработку за счёт параллельности.

---

## Как это работает в обычном Service (ClusterIP)

Допустим, у тебя `gateway-service` с `replicas: 2`. У сервиса есть один виртуальный IP (ClusterIP), например `10.43.5.100`.

```
                    ┌──────────────────┐
Клиент ─→ Service ─→│   ClusterIP      │─→ под gateway-1 (IP 10.42.0.5)
       (10.43.5.100)│  балансирует     │─→ под gateway-2 (IP 10.42.0.6)
                    └──────────────────┘
```

Когда приходит запрос на `gateway-service:8087`:
1. DNS возвращает **один IP** — ClusterIP сервиса.
2. kube-proxy на ноде через iptables/IPVS **случайно (round-robin)** выбирает один из подов.
3. Запрос летит в выбранный под.

Это и есть **балансировка**: один входной IP → распределение по подам.

---

## Почему PostgreSQL — `clusterIP: None` (headless)

Для БД балансировка **вредна**. Если у тебя 2 пода Postgres (postgres-0, postgres-1), и Service случайно отправит INSERT в один под, а SELECT в другой — данные не совпадут, потому что это **разные базы**.

Headless Service ведёт себя иначе:

```
                ┌───────────────────┐
Клиент ─→ DNS ─→│ Нет ClusterIP!    │
                │ Возвращает напрямую│
                │ IP подов:          │
                │  - postgres-0      │
                └───────────────────┘
```

DNS-запрос `postgres` возвращает **сразу IP пода** (или несколько IP, если реплик больше). Клиент сам решает, к какому конкретному поду подключаться — например, `postgres-0.postgres` (к мастеру), `postgres-1.postgres` (к реплике).

---

## Аналогия

- **Обычный Service (с балансировкой)** — это колл-центр: ты звонишь на один номер, и тебя случайно соединяют со свободным оператором. Все операторы делают одно и то же, тебе всё равно, кто ответит.

- **Headless Service** — это телефонный справочник: ты сам выбираешь, кому звонить — директору или бухгалтеру. У каждого своя роль, и подменять их нельзя.

---

## Кратко для защиты

> Балансировка — это автоматическое распределение запросов между несколькими подами одного сервиса. Обычный ClusterIP-сервис балансирует round-robin через kube-proxy. Для PostgreSQL я использую headless-сервис (`clusterIP: None`), потому что у БД балансировать запросы нельзя — клиент должен подключаться к конкретному поду по имени.
