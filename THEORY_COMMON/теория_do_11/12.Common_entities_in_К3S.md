## 🧱 Основные сущности в k3s (простыми словами)

**k3s** — это облегчённый Kubernetes, поэтому сущности в нём **те же самые**, что и в «большом» Кубернетесе. Просто некоторые компоненты «спрятаны» или упрощены.

Давай разберём всё по уровням — от «железа» до твоего приложения.

---

## 🗂️ Уровень 1: Инфраструктура (на чём всё работает)

| Сущность | Что это (простыми словами) | Зачем нужно | Аналогия |
|----------|-----------------------------|-------------|----------|
| **Node (Узел)** | Физическая или виртуальная машина, где работает Kubernetes | На ней запускаются контейнеры | 🏢 Здание, где сидят сотрудники |
| **Master / Control Plane** | «Мозг» кластера: управляет всем, принимает команды | Хранит состояние, раздаёт задачи воркерам | 🧠 Директор + секретарь + планировщик |
| **Worker (Воркер)** | «Рабочая лошадка»: запускает твои приложения | Здесь живут поды с твоими сервисами | 👷 Сотрудники, которые выполняют задачи |
| **etcd** | База данных «ключ-значение», где хранится всё состояние кластера | Без неё кластер «забудет», что запущено | 🗄️ Архив с документами компании |

> 💡 **В k3s**: etcd встроен в один бинарник, не нужно настраивать отдельно.

---

## 📦 Уровень 2: Запуск приложений (что ты создаёшь)

| Сущность | Что это | Зачем нужно | Простой пример |
|----------|---------|-------------|---------------|
| **Pod (Под)** | Минимальная единица запуска: 1 или несколько контейнеров вместе | Запустить приложение в изолированной среде | 📦 Коробка с приложением внутри |
| **Deployment** | Описывает, как запускать и обновлять поды (сколько копий, какой образ) | Масштабировать, обновлять без простоя | 📋 Инструкция: «Запусти 3 копии, обнови плавно» |
| **StatefulSet** | Как Deployment, но для приложений с состоянием (БД, очереди) | Гарантировать стабильные имена и хранилище | 🗂️ «Запусти БД с именем `postgres-0`, `postgres-1`...» |
| **DaemonSet** | Запускает по одному поду на **каждом** узле | Сбор логов, мониторинг, сетевые агенты | 🔍 «Поставь агента мониторинга на каждую машину» |
| **Job / CronJob** | Запускает задачу один раз или по расписанию | Бэкапы, отчёты, миграции БД | ⏰ «Запусти скрипт миграции в 3 ночи» |

---

## 🌐 Уровень 3: Сеть и доступ (как добраться до приложения)

| Сущность | Что это | Зачем нужно | Пример |
|----------|---------|-------------|--------|
| **Service (Сервис)** | Виртуальный IP, который «ведёт» к группе подов | Дать приложению стабильный адрес, даже если поды пересоздаются | 📞 Виртуальный номер колл-центра |
| **ClusterIP** | Тип Service: доступен только внутри кластера | Связь между сервисами | 🔒 Внутренний телефон |
| **NodePort** | Тип Service: открывает порт на каждом узле | Доступ извне для тестов | 🚪 Открытая дверь на каждом этаже |
| **LoadBalancer** | Тип Service: выдаёт внешний IP (в k3s — через ServiceLB) | Доступ из интернета | 🌐 Городской номер офиса |
| **Ingress** | «Умный маршрутизатор» для HTTP/HTTPS: домен → сервис | Один вход на много сервисов, + TLS | 🚦 Светофор + указатель: «api.example.com → сервис А» |
| **Ingress Controller** | Программа (например, Nginx), которая читает Ingress-правила и направляет трафик | Реализует логику Ingress | 👮 Охранник на входе, который читает список гостей |

> 💡 **В k3s**: по умолчанию стоит Traefik, но ты отключил его и поставил Nginx — это нормально.

## 🔐 Уровень 4: Конфигурация и секреты (настройки приложения)

| Сущность | Что это | Зачем нужно | Пример |
|----------|---------|-------------|--------|
| **ConfigMap** | Хранилище конфигураций (текст, переменные) | Не «зашивать» настройки в образ | ⚙️ Файл `config.ini` для приложения |
| **Secret** | Хранилище чувствительных данных (пароли, токены, ключи) в зашифрованном виде | Безопасно хранить пароли от БД, API-ключи | 🔑 Сейф с паролями |
| **ServiceAccount** | «Учётка» для пода, чтобы он мог обращаться к API Kubernetes | Дать приложению права на чтение/запись в кластере | 🪪 Пропуск с правами «только чтение» |

---

## 💾 Уровень 5: Хранение данных (чтобы данные не пропали)

| Сущность | Что это | Зачем нужно | Пример |
|----------|---------|-------------|--------|
| **PersistentVolume (PV)** | Кусок дискового пространства в кластере (реальное хранилище) | Хранить данные БД, файлы пользователей | 🗄️ Внешний жёсткий диск |
| **PersistentVolumeClaim (PVC)** | «Заявка» от пода: «Мне нужно 10 ГБ места» | Поду не думать, где брать диск — Kubernetes сам найдёт | 📝 Запрос в отдел ИТ: «Дайте мне диск на 10 ГБ» |
| **StorageClass** | Шаблон, как создавать PV автоматически (динамическое выделение) | Не создавать PV вручную для каждого PVC | 🏭 Конвейер: «PVC на 10 ГБ → создай PV на локальном диске» |

> 💡 **В k3s**: по умолчанию есть `local-path` StorageClass — PV создаются на диске хоста автоматически.

## 🧩 Уровень 6: Расширения (то, что добавляет k3s и cert-manager)

| Сущность | Что это | Зачем нужно |
|----------|---------|-------------|
| **CRD (Custom Resource Definition)** | «Инструкция», как добавить новый тип объекта в Kubernetes | Позволяет cert-manager, Prometheus и другим инструментам «встроить» свои объекты |
| **Certificate** (от cert-manager) | Описывает, какой сертификат выпустить и для какого домена | Автоматическая выдача и обновление TLS-сертификатов |
| **ClusterIssuer / Issuer** | «Удостоверяющий центр», который подписывает сертификаты | Выпускает сертификаты для Certificate-объектов |
| **ServiceLB** (в k3s) | Встроенный LoadBalancer-контроллер | Выдаёт внешний IP для Service типа `LoadBalancer` без облака |

## 🧭 Как это всё связано (упрощённая схема)

```
Ты (через kubectl)
       │
       ▼
kube-apiserver (принимает команды)
       │
       ▼
etcd (сохраняет состояние: «запусти 3 пода с образом nginx»)
       │
       ▼
kube-scheduler → назначает поды на узлы
       │
       ▼
kubelet на воркере → запускает контейнеры в подах
       │
       ▼
Service + Ingress → открывают доступ к подам снаружи
       │
       ▼
PV/PVC → подключают постоянное хранилище к БД
```

## 🧠 Короткая шпаргалка (запомни это)

```
🔹 Node = машина, где работает Kubernetes
🔹 Pod = минимальная единица запуска (контейнер + настройки)
🔹 Deployment = «инструкция», как запускать и обновлять поды
🔹 Service = виртуальный IP для доступа к подам
🔹 Ingress = маршрутизатор для HTTP/HTTPS (домен → сервис)
🔹 ConfigMap / Secret = настройки и пароли для приложения
🔹 PV / PVC = постоянное хранилище для данных
🔹 CRD = способ добавить новые типы объектов (Certificate, Issuer...)
🔹 В k3s: etcd, ServiceLB, local-path — уже встроены
```

## ❓ Частые вопросы

**В: А чем k3s отличается от «большого» Kubernetes по сущностям?**  
О: Сущности **те же самые**. Разница в том, что в k3s некоторые компоненты (etcd, ServiceLB, local-path) встроены и настроены «из коробки», чтобы не тратить время на ручную настройку.

**В: Обязательно ли использовать все эти сущности?**  
О: Нет. Ты используешь только те, что нужны твоему приложению. Например, если нет БД — не нужны PV. Если нет внешнего доступа — не нужен Ingress.

**В: Как узнать, какие сущности есть в моём кластере?**  
О: Команды:
```bash
kubectl get nodes          # узлы
kubectl get pods -A        # все поды во всех неймспейсах
kubectl get svc -A         # все сервисы
kubectl get ingress -A     # все Ingress
kubectl get pvc -A         # все заявки на хранилище
kubectl get crd            # все расширенные типы (CRD)
```
