## 🐝 k3s — простыми словами

**k3s** (произносится «кей-три-эс») — это **облегчённая версия Kubernetes**, созданная компанией Rancher (сейчас часть SUSE). Его главная фишка: **«всё, что нужно для продакшена, но в 5 раз легче»**.

> 🧩 **Аналогия из жизни:**
> 
> | Инструмент | Аналогия | Для чего |
> |-----------|----------|----------|
> | **Vanilla Kubernetes** | 🏭 Полноценный завод с цехами, отделом кадров, складом, охраной | Большие компании, сложные системы |
> | **k3s** | 🚐 Мобильная мастерская: всё необходимое, но компактно и быстро | Малый бизнес, крайние устройства (IoT), обучение |
> | **Minikube** | 🧰 Ящик с инструментами для домашней починки | Локальные тесты, «попробовать на коленке» |

---

## 🔍 Сравнение: k3s vs Vanilla Kubernetes vs Minikube

| Критерий | **Vanilla Kubernetes** | **k3s** | **Minikube** |
|----------|----------------------|---------|--------------|
| **Размер** | ~1.5 ГБ бинарников | ~50 МБ один бинарник | ~200 МБ + виртуалка |
| **Память (мин.)** | 4+ ГБ на мастер | 512 МБ на узел | 2+ ГБ на всю ВМ |
| **Установка** | Сложная: kubeadm, etcd, CNI, CSI вручную | Одна команда: `curl ... \| sh` | Одна команда, но нужна виртуализация |
| **etcd** | Отдельный компонент, настраивается вручную | Встроен по умолчанию (или SQLite для тестов) | Встроен в ВМ |
| **Ingress** | Нет, ставишь сам | **Traefik** по умолчанию (можно отключить) | Нет, ставишь сам |
| **Storage** | Нет, ставишь CSI-плагины | **Local Path Provisioner** встроен | Зависит от драйвера ВМ |
| **LoadBalancer** | Нет, нужно облако или MetalLB | **ServiceLB** (klipper-lb) встроен | Нет, только NodePort |
| **Продакшен** | ✅ Да, стандарт для крупных систем | ✅ Да, особенно для edge/IoT | ❌ Нет, только для тестов |
| **Обучение** | Сложно для старта | ✅ Идеально: просто, но «по-настоящему» | ✅ Хорошо для первого знакомства |

## 🧱 Что «вырезали» из k3s для лёгкости?

Разработчики убрали то, что редко нужно в малых сценариях:

| Убрано | Зачем | Чем заменено в k3s |
|--------|-------|-------------------|
| 🔹 Отдельные облачные провайдеры (AWS, GCP и т.д.) | Чтобы не тащить лишний код | Универсальные драйверы + возможность добавить при необходимости |
| 🔹 Устаревшие API (alpha, beta) | Чтобы уменьшить размер и упростить поддержку | Только стабильные `v1` API |
| 🔹 Некоторые драйверы хранения (in-tree) | Они тяжелые и редко используются | Современные CSI-плагины подключаются при необходимости |
| 🔹 Docker как runtime по умолчанию | Docker тяжелый и не всегда нужен | **containerd** (легче, быстрее, стандарт CNCF) |

> 💡 **Важно:** Это не «урезанный» Kubernetes, а **оптимизированный**. Все основные функции (Pods, Services, Deployments, Ingress, RBAC, Secrets) работают на 100% как в «большом» Kubernetes.

| Твоя задача | Почему k3s подходит |
|-------------|-------------------|
| 🔹 Поднять кластер из 3 узлов на одной машине | Потребляет мало ресурсов: 2 ГБ ОЗУ на узел — достаточно |

| 🔹 Сдать проект и показать реальные навыки | k3s — это **полноценный Kubernetes**, сертифицированный CNCF (Cloud Native Computing Foundation — фонд, развивающий облачные технологии). Ревьюер не отличит от «большого» по функционалу. |
| 🔹 Понять архитектуру, а не просто скопировать команды | Проще отлаживать: один бинарник, понятные логи, меньше «магии» |

## 🛠️ Практическая разница в командах

### Установка «большого» Kubernetes (упрощённо):
```bash
# На каждом узле:
# 1. Установить kubeadm, kubelet, kubectl
# 2. Настроить containerd/Docker
# 3. Инициализировать кластер: kubeadm init
# 4. Настроить сеть: kubectl apply -f calico.yaml
# 5. Присоединить воркеры: kubeadm join ...
# 6. Поставить Ingress, Storage, DNS...
# Итого: 50+ команд, много ручной настройки
```

### Установка k3s:
```bash
# На мастере:
curl -sfL https://get.k3s.io | sh -s - --disable=traefik

# На воркерах:
curl -sfL https://get.k3s.io | K3S_URL=https://<IP>:6443 K3S_TOKEN=<TOKEN> sh -

# Готово. Кластер работает.
```

### Управление — одинаковое:
```bash
# И в k3s, и в vanilla Kubernetes:
kubectl get nodes
kubectl apply -f deployment.yaml
kubectl logs my-pod
```

> 🧠 **Запомни:** Разница — в **установке и настройке**, а не в **использовании**. Как только кластер запущен, ты работаешь с ним через стандартный `kubectl`.

## 🧩 Когда что выбирать?

| Сценарий | Что выбрать | Почему |
|----------|------------|--------|
| 🔹 «Хочу попробовать Kubernetes впервые» | **Minikube** | Проще всего: одна команда, не нужно думать о сети и узлах |
| 🔹 «Делаю учебный проект, нужен кластер из нескольких узлов» | ✅ **k3s** | Легко масштабируется, мало ресурсов, «как настоящий» |
| 🔹 «Готовлюсь к работе в крупной компании с продакшен-кластером» | **Vanilla Kubernetes** (или managed: Yandex Cloud, GKE) | Нужно понимать «внутренности»: etcd, CNI, CSI, RBAC на глубоком уровне |
| 🔹 «Разворачиваю приложение на краю сети (завод, магазин, дрон)» | ✅ **k3s** | Работает на слабых устройствах, автообновление, низкие требования |
| 🔹 «Нужен кластер для продакшена в облаке» | **Managed Kubernetes** (Yandex Cloud, AWS EKS) | Не хочешь админить master-узлы, платишь за удобство |

## ❓ Частые вопросы

**В: А можно ли потом перейти с k3s на «большой» Kubernetes?**  
О: Да! Манифесты (YAML-файлы) совместимы на 99%. Разница только в установке и некоторых деталях (например, как работает StorageClass).

**В: Почему в k3s по умолчанию Traefik, а не Nginx Ingress?**  
О: Потому что Traefik легче и проще в настройке «из коробки». Но ты можешь отключить его (`--disable=traefik`) и поставить Nginx — как ты и делаешь в проекте.

**В: А если мне потом понадобится функция, которой нет в k3s?**  
О: Почти всё можно добавить: CSI-плагины для хранения, CNI для сети, облачные интеграции. k3s не блокирует расширения — он просто не включает их по умолчанию.
