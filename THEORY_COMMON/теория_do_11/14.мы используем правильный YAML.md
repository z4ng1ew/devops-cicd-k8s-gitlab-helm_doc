# Этап 4. Установка Prometheus Operator

Цели по чек-листу простые:
1. Поставить **Prometheus Operator** — оператор (operator — программа-«робот» внутри Kubernetes, которая следит за специальными ресурсами и сама разворачивает компоненты Prometheus/Grafana/Alertmanager)
2. Показать `kubectl get pods -n monitoring`

Самый простой и стандартный способ — поставить **kube-prometheus-stack** через **Helm**. Это «пакет», который ставит сразу: Prometheus Operator + Prometheus + Grafana + Alertmanager + node-exporter + kube-state-metrics одной командой.

---

## Шаг 1. Установка Helm (если ещё не стоит)

Helm — это «менеджер пакетов» для Kubernetes (как `apt` для Debian или `pip` для Python). Пакеты в Helm называются **chart** (диаграмма).

```bash
# Проверим, есть ли уже
helm version 2>/dev/null || echo "Helm не установлен"
```

Если нет — ставим официальным скриптом:

```bash
curl -fsSL https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
helm version
```

📸 **СКРИНШОТ**: `helm version` — версия Helm 3.x.

## Шаг 2. Добавляем репозиторий prometheus-community

```bash
# Добавляем источник чартов от сообщества Prometheus
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts

# Обновляем индекс (список доступных чартов)
helm repo update
```

## Шаг 3. Создаём namespace monitoring

Чек-лист напрямую требует команду `kubectl get pods -n monitoring`. Значит, всё должно быть именно в этом неймспейсе.

```bash
kubectl create namespace monitoring
```

## Шаг 4. Установка kube-prometheus-stack

Это **главная команда**. Она ставит сразу весь набор мониторинга в namespace `monitoring`.

Чтобы у нас не разворачивались огромные дашборды и тяжёлые компоненты (нам нужен минимальный рабочий набор для зачёта, а не production), сделаем установку с урезанными ресурсами:

```bash
helm install kube-prometheus prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --set grafana.adminPassword='admin' \
  --set prometheus.prometheusSpec.resources.requests.memory=400Mi \
  --set prometheus.prometheusSpec.resources.limits.memory=800Mi \
  --set prometheus.prometheusSpec.retention=2d \
  --set alertmanager.alertmanagerSpec.resources.requests.memory=64Mi \
  --set alertmanager.alertmanagerSpec.resources.limits.memory=128Mi
```

Поясняю флаги:
- `helm install kube-prometheus` — это имя «релиза» (release — конкретная инсталляция чарта)
- `prometheus-community/kube-prometheus-stack` — какой чарт ставим (репозиторий/имя)
- `--namespace monitoring` — куда
- `--set ...` — точечная настройка значений (override — переопределение дефолтов чарта)
- `grafana.adminPassword='admin'` — пароль для входа в Grafana под admin (по умолчанию был бы случайный, и его пришлось бы доставать командой)
- `prometheus.prometheusSpec.retention=2d` — хранить метрики только 2 дня (вместо 10 дней по умолчанию). Нам метрики нужны на пару минут — чтобы скриншот сделать. Экономим место на диске ВМ.
- `resources.requests.memory=400Mi` — резервируем 400 МБ ОЗУ для Prometheus (по умолчанию он хочет 2 ГБ — это много для наших ВМ-ок с 2 ГБ ОЗУ каждая)

Установка займёт **2-5 минут**. Helm сначала молча подождёт, пока всё развернётся, потом покажет статус.

Ожидаемый вывод:
```
NAME: kube-prometheus
LAST DEPLOYED: ...
NAMESPACE: monitoring
STATUS: deployed
REVISION: 1
...
```

📸 **СКРИНШОТ**: вывод `helm install` со статусом `deployed`.

## Шаг 5. Главная проверка для чек-листа

```bash
kubectl get pods -n monitoring
```

Должно показать примерно 10-12 подов:

```
NAME                                                       READY   STATUS    RESTARTS   AGE
alertmanager-kube-prometheus-kube-prome-alertmanager-0     2/2     Running   0          3m
kube-prometheus-grafana-xxxxx                              3/3     Running   0          3m
kube-prometheus-kube-prome-operator-xxxxx                  1/1     Running   0          3m
kube-prometheus-kube-state-metrics-xxxxx                   1/1     Running   0          3m
kube-prometheus-prometheus-node-exporter-xxxxx             1/1     Running   0          3m
kube-prometheus-prometheus-node-exporter-yyyyy             1/1     Running   0          3m
kube-prometheus-prometheus-node-exporter-zzzzz             1/1     Running   0          3m
prometheus-kube-prometheus-kube-prome-prometheus-0         2/2     Running   0          3m
```

📸 **СКРИНШОТ (главный для пункта 4)**: вывод `kubectl get pods -n monitoring` — все поды в Running. **Это и есть прямое требование чек-листа** методички DO11:
> «Продемонстрировать в отчете результат выполнения команды `kubectl get pods -n monitoring`»

Жди, пока **все** поды перейдут в `Running`. Может занять до 5 минут на первой установке (нужно скачать ~7 образов из интернета — node-exporter, kube-state-metrics, prometheus, grafana, alertmanager, и т.д.). Эти образы НЕ предзагружены в containerd (в отличие от наших src-* образов), поэтому они подтянутся из публичных реестров. Интернет на ВМ-ах есть — multipass даёт его через NAT.

Если какой-то под застрял в `ContainerCreating` дольше 5 минут:
```bash
kubectl describe pod <имя_пода> -n monitoring | tail -20
```

Скорее всего там будет «Pulling image...» — просто подожди ещё, или образ большой.

## Шаг 6. Дополнительные проверки (для повышения оценки)

Не обязательны, но добавляют веса отчёту:

### Что именно поставилось

```bash
# Что добавил оператор - какие новые CRD появились
kubectl get crds | grep monitoring.coreos.com
```

Должно быть около 10 строк: `prometheuses.monitoring.coreos.com`, `alertmanagers.monitoring.coreos.com`, `servicemonitors.monitoring.coreos.com`, `prometheusrules.monitoring.coreos.com` и т.д. **Это и есть «расширение» Kubernetes, которое внёс Prometheus Operator** — оператор учит k8s понимать новые типы объектов.

📸 **СКРИНШОТ**: вывод `kubectl get crds | grep monitoring.coreos.com` — это **прямое доказательство** того, что Operator действительно работает (не просто «развернуты поды», а добавлены кастомные ресурсы).

### Список Services

```bash
kubectl get svc -n monitoring
```

Видишь сервисы для Prometheus (порт 9090), Grafana (3000), Alertmanager (9093).

📸 **СКРИНШОТ**: вывод `kubectl get svc -n monitoring`.

### Сам Prometheus как ресурс

```bash
# Это не Deployment, а специальный объект, который понимает Operator
kubectl get prometheus -n monitoring
kubectl get alertmanager -n monitoring
kubectl get servicemonitor -n monitoring
```

`kubectl get prometheus` — без оператора такая команда выдала бы ошибку «unknown resource». Она работает только потому, что Prometheus Operator добавил соответствующий CRD.

📸 **СКРИНШОТ (бонусный, для глубокого понимания)**: вывод `kubectl get prometheus,alertmanager,servicemonitor -n monitoring`.

### Зайти в Prometheus и Grafana через port-forward

`port-forward` — это «туннель» от твоего хоста до пода внутри кластера. Удобно для отладки и демонстрации.

```bash
# В одном терминале (запустить и оставить открытым)
kubectl port-forward -n monitoring svc/kube-prometheus-kube-prome-prometheus 9090:9090
```

Открой в браузере: http://localhost:9090 — увидишь UI Prometheus. Зайди в **Status → Targets** — там список всего, что Prometheus мониторит.

📸 **СКРИНШОТ**: страница Prometheus Targets (видны зелёные UP-статусы targets) — **очень эффектный скриншот для отчёта**.

Аналогично для Grafana:
```bash
# В другом терминале
kubectl port-forward -n monitoring svc/kube-prometheus-grafana 3000:80
```

Открой http://localhost:3000, логин `admin` / пароль `admin`. Внутри уже преднастроены десятки дашбордов — заходи в **Dashboards → Browse** и выбирай любой (например, «Kubernetes / Compute Resources / Cluster»).

📸 **СКРИНШОТ (бонусный, очень красиво)**: дашборд Grafana с графиками твоего кластера.

Если что-то не пойдёт — пиши, разберёмся. Ожидаемые проблемы:

| Проблема | Скорее всего причина |
|---|---|
| `helm install` падает с timeout | Не хватает памяти/CPU в кластере — попробуй уменьшить значения ещё, или перезапустить |
| Поды Prometheus в `Pending` | PVC не может привязаться — добавь `--set prometheus.prometheusSpec.storageSpec.volumeClaimTemplate.spec.storageClassName=local-path` (local-path-provisioner есть в k3s по умолчанию) |
| Поды в `ImagePullBackOff` | Интернет на ВМ-ах не работает или DNS барахлит — проверь `multipass exec k3s-master -- curl -I https://google.com` |
